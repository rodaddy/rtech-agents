# E2E evidence transcripts

Machine-written proof that a fully typed, bus-first round-trip completed against
the **live** fleet NATS bus. Generated by `scripts/e2e_evidence.py`.

Only this `README.md` is committed; `.gitignore` ignores everything else under
`.evidence/` (the `!.evidence/README.md` negation keeps this file tracked). Each
run writes a fresh `.evidence/webchat-<ts>.json` transcript that is NOT committed.

## Regenerate

```bash
uv run python scripts/e2e_evidence.py
```

Environment knobs:

| Env var                  | Default                     | Effect                                             |
|--------------------------|-----------------------------|----------------------------------------------------|
| `E2E_ENGINE`             | `scripted`                  | `scripted` (deterministic) or `claude` (real SDK). |
| `RTECH_WEBCHAT_NATS_URL` | `nats://127.0.0.1:4222`   | Live fleet NATS bus URL.                           |
| `E2E_MODEL`              | `claude-sonnet-5`           | Model id used only when `E2E_ENGINE=claude`.       |

The `claude` engine additionally requires `ANTHROPIC_API_KEY` or
`ANTHROPIC_BASE_URL`; without one the script logs the reason and exits 2.

`result == "PASS"` if and only if the process exits 0. Exit 2 means the run could
not start (bus unreachable or engine unavailable); exit 1 means a proof step
failed (the transcript is still written with the failure recorded).

## Transcript shape (`webchat-<ts>.json`)

Top-level keys:

| Key           | Meaning                                                                 |
|---------------|-------------------------------------------------------------------------|
| `ts`          | UTC timestamp (`YYYYMMDDTHHMMSSZ`) — also the filename suffix.           |
| `issue`       | `22`.                                                                    |
| `engine`      | Which engine ran: `scripted` or `claude`.                               |
| `transport`   | `live-nats`.                                                             |
| `nats_url`    | The live bus URL used.                                                   |
| `agent`       | The agent id (`agentd`).                                                 |
| `task_id`     | The fixed task id minted up front (known before any publish).           |
| `steps`       | Ordered proof steps with per-step `ok` (and `reason` on failure).       |
| `assertions`  | The pass/fail assertion block (see below).                              |
| `ws_messages` | Redacted browser-facing WS payloads, mirroring the app's WS forward.    |
| `frames`      | Ordered, timestamped log of every captured frame (see element shape).   |
| `result`      | `PASS` or `FAIL`.                                                        |

Each `frames[]` element:

```json
{
  "seq": 1,                                  // 1-based arrival order
  "ts": "2026-07-11T13:30:00.000000+00:00",  // ISO-8601 UTC capture time
  "subject": "rtech.task.new",               // the NATS lane it crossed
  "frame_type": "TaskFrame",                 // TaskFrame|TurnFrame|StatusFrame|SteerFrame
  "payload": { ... }                         // frame.model_dump(mode="json"), redacted
}
```

### Assertions (all must hold for `result == "PASS"`)

| Assertion                     | Meaning                                                         |
|-------------------------------|----------------------------------------------------------------|
| `task_frame_published`        | A `TaskFrame` was captured on `rtech.task.new`.                 |
| `turn_rendered_ws`            | A WS `turn` message was rendered back through the WS path.      |
| `steer_reflected`             | A `TurnFrame` acknowledging the mid-turn steer was captured.   |
| `done_derived_result_fired`   | The orchestrator DERIVED done and fired the result lane.       |
| `no_done_token_in_frames`     | Zero forbidden tokens in any frame payload (bus-first floor).  |
| `forbidden_token_hits`        | List of any forbidden tokens found (must be empty).            |

### Redaction

Every frame `payload` and every `ws_messages` entry is recursively redacted
before writing: concrete values of secret-shaped env vars
(`*TOKEN*`/`*SECRET*`/`*KEY*`/`*PASSWORD*`/`*CREDENTIAL*`/`*API*`, length ≥ 8)
and token shapes (`sk-…`, `gh[porus]_…`, `xox[baprs]-…`, JWT `eyJ….….…`) are
replaced with `«redacted»`. Raw secret values are never logged or written.
